# 初期化子リスト — 宣言と同時に値を入れる

## 今日のゴール

`int a[3] = {1, 2, 3};` と `char s[6] = "hello";` を、
ローカル変数でもグローバル変数でも書けるようにする。

## この回の位置づけ

- 言語機能発展シリーズ（選択制）。前提はコマ14（グローバル変数）
- コマ14 の資料が「配列や構造体の初期化リスト、文字列による初期化は扱わない」と
  明示的に先送りした宿題の回収
- `mycc.py` も `scaffold/parser.py` も書き換えない。
  ラッパー `langcc.py`（完成品）がパーサとコード生成の両方に差し込む
- 編集するのは `initializer.py` の3つの関数

## いまはどうなっているか

```c
int a[3] = {1, 2, 3};
```

いまのコンパイラに食わせると、**構文解析で止まる**。

```text
構文解析エラー: [line 1] 式が期待されましたが '{' がありました
```

`=` の右側は式として読まれるが、C の式は `{` で始まらない。
`{...}` は**初期化子**という、式とは別の構文である。

そのため、この回では2か所に手を入れる必要がある。

| 段階 | 追加すること |
|------|-------------|
| 構文解析 | `{ e1, e2, ... }` を読んで木にする |
| コード生成 | 各要素を、正しい場所に書き込む |

構文解析側はラッパーが用意する（F2〜F4 で作ったパーサの拡張と同じ形で、
`parse_expr` の先頭に「`{` なら初期化子リスト」の分岐を足しているだけである）。
できる木はこうなる。

```text
kind='InitList'、args=[Num(1), Num(2), Num(3)]
```

## 書かなかった要素は 0 になる

C には、初期化子について明確な規則がある。

```c
int a[5] = {7, 8};     /* a[2], a[3], a[4] は 0 になる */
int b[3] = {};         /* 全部 0 */
```

**足りない分は 0 で埋める。** これは「たまたま 0 だった」ではなく、
規格で決まった動作である（コマ14 で見た `.bss` が0クリアされるのと同じ考え方）。

文字列による初期化も同じ枠組みで扱える。

```c
char s[6] = "hello";   /* 'h','e','l','l','o','\0' */
char t[8] = "hi";      /* 'h','i','\0', 0,0,0,0,0 */
```

文字列リテラルは「文字コードの並び + NUL 終端」なので、
`{104, 101, 108, 108, 111, 0}` と書いたのと同じことになる。

## ローカルとグローバルで作り方が違う

ここがこの回の面白いところである。同じ `= {1,2,3}` でも、
置き場所によって**まったく違うもの**が出力される。

| | ローカル（スタック） | グローバル（`.data`） |
|---|---|---|
| いつ値が入るか | 実行時（関数に入るたび） | 実行前（プログラムの一部として） |
| 出力するもの | **命令**（`li` と `sw`） | **データ**（`.word` 列） |

```asm
;; ローカル: int a[3] = {1,2,3};
  li a0, 1
  addi a1, s0, -24
  sw a0, 0(a1)
  li a0, 2
  addi a1, s0, -20     ← 要素サイズぶん進む
  sw a0, 0(a1)
  ...
```

```asm
;; グローバル: int g[4] = {10,20,30,40};
  .data
  .globl g
g:
  .word 10
  .word 20
  .word 30
  .word 40
```

グローバルのほうは**命令が1つも要らない**。
実行ファイルの中に値がそのまま埋め込まれ、OS がメモリに読み込んだ時点で
初期化が終わっている。コマ14 の `.data` / `.bss` の話が、ここで効いてくる。

::: note

**だから「グローバルの初期値は定数だけ」なのか。**
コマ14 で「グローバル変数の初期値は整数定数だけに限定する」と書いたのは、
実行前に値が決まっていなければ `.word` に書けないからである。
`int g = f();` が書けないのは、コンパイラの手抜きではなく、
**そもそも実行前に値が存在しない**からである。

:::

## 発展課題

1. **サイズの省略**: `int a[] = {1,2,3};` は要素数を初期化子から決める。
   配列の大きさが決まるのはパーサか、コード生成か。どちらで直すべきか
2. **構造体の初期化**: `Point p = {3, 4};` を追加する。
   配列と違い、要素ごとに**サイズもオフセットも違う**（コマ12 の `_struct_defs` を使う）
3. **入れ子の初期化子**: `int m[2][2] = {{1,2},{3,4}};`
   （多次元配列は Core プロファイル外なので、まず型の表現から考える必要がある）
4. **文字列リテラルとの違い**: `char s[] = "hi";` と `char *p = "hi";` は
   まったく違うものである。前者は**コピー**、後者は `.data` への**参照**。
   生成コードを見比べて確かめる
5. **B1 と組み合わせる**: `int a[3] = {1+1, 2*3, 10/2};` は動くか。
   定数畳み込み（B1）があれば `.word 2 / .word 6 / .word 5` にできる

::: note

**コラム: 初期化と代入は違う。**
`int a[3] = {1,2,3};` は初期化、`a = {1,2,3};` は（C では）書けない。
配列には代入できないからである。
一方 `int x = 5;` と `int x; x = 5;` は、C ではほぼ同じ意味になる
（C++ では意味が違う場面がある）。
「宣言と同時に値を与える」ことを別扱いにするのは、
**まだ何も入っていない場所に最初の値を置く**という、代入とは別の操作だからである。

:::
