# C 移植・セルフホスト — Python 版を C で書き直す

## このトピックのゴール

**Python 版コンパイラを C 言語で丸ごと書き直し、最終的に自分自身をコンパイルできる状態
（セルフホスト）を目指す**。
これまでの発展課題は1トピック=1回で完結したが、この回だけは性質が違う。
「これが通れば完了」という単一の判定は無く、

## 基本方針: アルゴリズムを再発明しない

移植は「もう一度コンパイラを設計する」ことではなく、
**すでに動いている Python 版のデータ構造を C に写す**作業である。

| Python | C |
|--------|---|
| class / dataclass | `struct` |
| `dict` | 連結リスト（線形探索） |
| `list.append` | 末尾連結 |
| `None` | `NULL` |
| `isinstance(node, AddNode)` | `node->kind == ND_ADD` |

コンパイラの論理（どの順で何をたどるか）は Python 版で完成させたものをそのまま流用する。
ここで新しいアルゴリズムを考え出そうとすると、範囲が発散して終わらなくなる。

## 大まかな進め方

1. **データ構造の移植**: `struct Node`・`struct Type`・シンボルテーブル・`emit()` をまず C に写す
2. **コード生成の移植**: 算術式・変数・制御構文 → 関数・ポインタ → 配列・構造体・グローバル変数、
   の順に Python 版のコード生成ロジックを C に写していく
3. **フロントエンド**: `scaffold/lexer.py` / `parser.py` を読解して移植する。
   発展課題 F 系列（F1〜F4）に先に取り組んでおくと、このフロントエンド移植がかなり楽になる
4. **セルフホストへの挑戦**: `#include` / `#define` の前処理を自分で実装し、
   Stage 0（gcc で自分の C 版をビルド）→ Stage 1（Stage 0 でできた自分のコンパイラで、
   もう一度自分自身をビルド）という段階を踏んで確認する

最初の目標は、算術式・変数・制御構文までを C 版で出力できるようにすることに置くとよい。
一気に全部を移植しようとせず、Python 版のコマ順（コマ2〜15 の積み上げ）をそのまま
移植の順番として使える。

## C 実装の規約

| 項目 | 規約 |
|------|------|
| 言語 | Core プロファイル自身で書く（セルフホスト可能な範囲に収める） |
| 命名規則 | 型 `snake_case` / 関数 `snake_case` / 定数 `UPPER_SNAKE` |
| メモリ管理 | `malloc` のみ使用。`free` は不要（コンパイラはプロセス終了時に一括解放） |
| エラー処理 | `fprintf(stderr, ...)` + `exit(1)` で即終了 |
| コメント | `//` 一行コメントのみ |

**命名規約について**: 本仕様は予約語を12語だけに絞っているため（`language_spec.md` の例外 E2）、
C の他のキーワード（`typedef` や `switch` など）を識別子として使うことができる。
しかし Stage 0 は gcc でビルドするので、その名前は通常の C コンパイラでもビルドできる
必要がある。**C のキーワードを自分のソースの識別子に使わないこと。**

RV64 の呼び出し規約とアラインメント規則は `rv64_reference.md` を参照。

## セルフホストの検証

雛形は用意しない。以下の段階を自分のビルドスクリプトで踏めばよい。

```bash
gcc -o mycc_stage0 src/*.c                       # Stage 0: gcc でビルド
./mycc_stage0 src/*.c -o mycc_stage1             # Stage 1: 自分でビルド
python3 scaffold/test_runner.py --compiler ./mycc_stage1 --tests final/tests
```

**なぜ段階を踏むか**: セルフホストは「動いた気がする」状態になりやすい。
どの段階の成果物でテストを通したのかを自分で明示的に確認する必要がある。

参考達成条件（必達目標ではない）: `mycc_stage1` の生成成功 + `final/tests`（[fixed17](../../workbook/advanced/README.md#fixed17)）全通 +
前処理（`#include` / `#define`）の自前実装が動くこと。
